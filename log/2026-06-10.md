## What Was Done Today

### 1. RQ Worker — Windows `os.fork` Fix (`backend/app/worker.py`)

RQ's default `Worker` class uses `os.fork()` which is POSIX-only and doesn't exist on
Windows (Python 3.13). Fixed with platform detection:

- **Windows:** `SimpleWorker` (runs jobs in-process, no forking) — correct for dev
- **Linux/Mac:** standard forking `Worker` with `with_scheduler=True` — correct for production

`SimpleWorker.work()` called without `with_scheduler=True` (not needed for basic job execution).

---

### 2. IDP Pipeline (`backend/app/modules/idp/`)

Full async text-extraction pipeline, cost-cascade design:

| File | Description |
|---|---|
| `parsing.py` | PyMuPDF helpers: `open_pdf`, `extract_text_layer`, `has_usable_text_layer`, `rasterize_page` (PNG, for OCR + future VLM input) |
| `ocr.py` | RapidOCR singleton wrapper — lazy init, CPU-only. `ocr_image(png_bytes) → (text, confidence)` |
| `pipeline.py` | Orchestrator `run_extraction(file_bytes, mime_type) → ExtractionResult`. Text-layer first (free); OCR only when no usable text layer exists. |
| `jobs.py` | `process_document(doc_id, tenant_id)` — RQ job entry. Status transitions, persist extraction + `search_tsv`, `ProcessingJob` tracking, `ActivityEvent` on complete/fail. |
| `queue.py` | `enqueue_document(doc_id, tenant_id)` — single public seam. RQ `Retry(max=3, interval=[10,30,60])` for resilience. |

**Cost cascade:** digital PDFs → free text-layer (PyMuPDF), zero OCR cost. OCR only on
scanned docs/images with no usable text layer. GPU/VLM not invoked this milestone.

**Dependency deviation:** `liteparse` (Rust beta, unstable on Windows) replaced with
`rapidocr-onnxruntime` (pip-only, CPU, Windows-friendly). Noted as deliberate deviation
from CLAUDE.md §2 which originally listed LiteParse.

### 3. Enqueue on Upload (`backend/app/modules/files/service.py`)

After-commit hook pattern: `event.listen(db, "after_commit", ...)` captures `(doc_id, tenant_id)` pairs and calls `enqueue_document` after the transaction commits. Avoids the
worker racing an uncommitted row. Wired in both `create_documents` and `retry_document`.

## DB vs Object Storage Split (as of Milestone C)

| Store | What lives there |
|---|---|
| **Object Storage** (Supabase Storage, private `documents` bucket) | Raw file bytes only, at `{tenant_id}/docs/{doc_id}.{ext}` |
| **Postgres** | Metadata (filename, mime, size, status, page_count, flags), `extracted_text`, `search_tsv` (TSVECTOR + GIN index), processing state (`ProcessingJob`), audit events (`ActivityEvent`) |

File bytes never touch the database — object storage is far cheaper per GB and keeping bytes
out of Postgres keeps the DB small and fast.
