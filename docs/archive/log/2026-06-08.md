### 3. JWT Verification Fix — `security.py`

**Problem:** `PyJWT` raised `"The specified alg value is not allowed"` — a zombie uvicorn
process from an earlier restart was still serving on port 8000 with stale code. New code
never loaded.

**Root cause diagnosed:**
- `jwt.get_unverified_header(token)` confirmed the token uses HS256 (anon key verified
  successfully against the raw UTF-8 JWT secret in a diagnostic script).
- The error was always from the stale process, not the new code.

**Fix applied:**
- `security.py` rewritten to support **both** HS256 (legacy shared secret) and ES256/RS256
  (modern Supabase asymmetric signing via JWKS endpoint at
  `{SUPABASE_URL}/auth/v1/.well-known/jwks.json`). Handles future Supabase projects that
  switch to asymmetric keys without code changes.
- Backend moved to **port 8001** (zombie occupied 8000); frontend `.env.local` updated to
  point at 8001.

### 4. `DetachedInstanceError` Fix — `auth/service.py`

**Problem:** `pydantic_core.ValidationError: 8 validation errors for UserOut — DetachedInstanceError`
— Pydantic tried to read SQLAlchemy ORM attributes **after** `db.close()` was called in
the `finally` block. SQLAlchemy expires all attributes on commit; after close, the session
is detached and attributes can't reload.

**Fix:** Added `db.refresh(user)` and `db.refresh(tenant)` between `db.commit()` and
`db.close()`. This loads all column attributes into the object's `__dict__` while the
session is still open; they remain accessible after detachment.
